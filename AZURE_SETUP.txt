SUGGESTED TWO FUNCTION CONTRACTS (write the implementations yourself)
1. Game summary
   Function route: GET /api/game-summary?title=...
   API route:      GET /api/cloud/game-summary?title=...
   Response idea:  {"title":"Example","characterCount":7}
   Treat this as string processing, not a generated factual game synopsis.
2. Playtime estimate
   Function route: GET /api/playtime-estimate?games=3&hoursPerGame=20
   API route:      GET /api/cloud/playtime-estimate?games=3&hoursPerGame=20
   Response idea:  {"games":3,"hoursPerGame":20,"totalHours":60}
   Validate query input, missing values, and overflow/invalid ranges.
Both can run without database storage, which the assignment permits.
Choose function names and explicit HTTP trigger routes to match these URLs.
Define separate request/response objects if helpful. Use one business method
per function, encode query strings, handle HTTP errors, and preserve JSON.

LOCAL DEVELOPMENT
Install .NET 10, Azure Functions Core Tools v4 with .NET 10 support, and
Azurite (local storage emulator). With Visual Studio, use current Azure tooling.
1. Copy src/GameLibrary.Functions/local.settings.example.json to
   src/GameLibrary.Functions/local.settings.json (ignored by Git).
2. Start Azurite. UseDevelopmentStorage=true refers to that local emulator.
3. Implement the two HTTP functions. Empty classes register no functions.
4. In a terminal inside src/GameLibrary.Functions, run:
     func start --port 7071
   The host should list both routes AFTER you implement them.
5. In another terminal from repo root, run:
     dotnet run --project src/GameLibrary.Api --launch-profile GameLibrary.Api
6. In another terminal from repo root, run:
     dotnet run --project src/GameLibrary.Client -- http://localhost:5106/
appsettings.json sets AzureFunctions:BaseUrl to http://localhost:7071/.
Use function relative paths beginning api/ so the HTTP route prefix is kept.
Do not add an extra api/ to BaseUrl and then duplicate it in the path.
